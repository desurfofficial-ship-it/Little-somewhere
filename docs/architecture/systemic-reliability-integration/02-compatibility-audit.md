# 02 — Compatibility Audit (Reliability Changes vs Current Main)

**Method**: for every reliability change, (1) inspect the current-main implementation, (2) inspect the reliability implementation, (3) inspect main-side commits that touched the subsystem since the old base `545e323`, (4) compare behavior (not just lines), (5) decide preserve / adapt / replace / omit, (6) back it with a regression test. Independent verification was re-done by two round-1 adversarial reviewers; their disproof evidence is folded into the rows below.

## 1. Overlap scan result

`git diff --stat 545e323..0273821 -- src/game/` shows main changed exactly: `dialogue/assets.ts` (+91), `environment.ts` (+26), `progressionVisuals.ts`/`.test.ts` (new, +878). The five reliability-modified files have **zero** main-side drift, so the cherry-picks applied textually clean. The audit below therefore focuses on *behavioral* compatibility: whether each reliability rule still matches current-main production writers, and whether main's new code interacts with the capped/sanitized collections.
