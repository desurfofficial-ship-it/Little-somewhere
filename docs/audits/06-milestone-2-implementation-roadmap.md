## 2. Recommended Implementation Order (4 Phases)

### Phase A — Foundation: Schema v2 Migrations, Time/RNG, & Headless Navigation
**Why first**: Extracting `WorldState v2` persistence and waypoint navigation creates a stable, Node-testable foundation before any new AI or dialogue state is stored.
- **Work items**:
  1. Add `src/game/rng.ts` and `src/game/time.ts` (unify `DAY_END_MINUTE = 1290`, add `SeasonType`, `DAYS_PER_SEASON`).
  2. Create `src/game/migrations.ts` and upgrade `src/game/storage.ts` (`schemaVersion: 2`, `migrateV1ToV2`, `sanitizeWorldState`, backup key).
  3. Create `src/game/navigation.ts` with 22–28 lane `NAV_NODES`, `computeWaypointPath()`, and actor separation.
  4. Write `storage.test.ts` and expand `worldMap.test.ts` (including `reconciled = true` slots and cross-pond paths).
- **Risk**: Low. Zero visual regressions; 100% tested in Node.

### Phase B — Pure Life Simulation & Bilateral Relationships
**Why second**: Moving NPC simulation out of `NeighborhoodCanvas.tsx` into `src/game/npcSimulation.ts` requires `navigation.ts` and `WorldState.npcRuntime` from Phase A.
- **Work items**:
  1. Create `src/game/relationships.ts` (`PlayerNpcRelation`, `NpcNpcRelation`, `getHeartLevel`, daily affinity cap fixing trust farming).
  2. Add `ResidentTraits` (`residents.ts`) and build `src/game/npcSimulation.ts` (seeded activity scoring, `SocialEncounter` pairing, headless `stepNeighborhoodSimulation()`).
  3. Update `NeighborhoodCanvas.tsx` to delegate NPC movement/clock to `stepNeighborhoodSimulation()` and drive `NpcAnimationState` poses (`idle`, `walk`, `work`, `sketch_read`, `music`, `converse`, `admire`).
  4. Update `JournalDrawer.tsx` to show live `npcRuntime[id].currentPlaceName` & `currentActivityLabel`.
  5. Write `simulation.test.ts` and `relationships.test.ts`.
- **Risk**: Medium (refactoring `tick()` ownership out of `NeighborhoodCanvas.tsx`). Mitigated by running headless `simulation.test.ts` + browser QA immediately after wiring.

### Phase C — Declarative Dialogue Engine & Milestone 1 Defect Fixes
**Why third**: Declarative `DialogueTopic[]` conditions directly consume `relationships.ts` (Phase B) and `WorldEventRecord` history generated by `npcSimulation.ts`.
- **Work items**:
  1. Create `src/game/dialogueEngine.ts` (`DialogueTopic`, `DialogueCondition`, `WorldEventRecord`, `TopicHistoryEntry`, deterministic selector + daily fallback pool).
  2. Migrate all 9 residents' *The Silent Gazebo Bell* branches from `narrative.ts` into declarative topics, fixing the verified `nora_read_together` memory omission and `toby_clapper` / quest-cue alignment.
  3. Add Milestone 2 reusable daily/weather/season/gossip topics (`npc_gossip` referencing recent `SocialEncounter`s and `event_reaction` topics).
  4. Update `actions.ts` (`applyDialogueChoice` enforces daily affinity cap, records `topicHistory`, emits `WorldEventRecord`) and add defensive node lookup in `DialogueSheet.tsx`.
  5. Write `dialogue.test.ts` validating all branches, node integrity, and cooldowns.
- **Risk**: Medium (regression risk on existing story branches). Mitigated by keeping all existing choice/flag/memory IDs and testing every branch in `dialogue.test.ts`.

### Phase D — 5-Layer Environment, Weather/Season Visuals & Performance Polish
**Why fourth**: Weather and seasonal palettes tie into NPC routines (`rainBehavior`), dialogue (`weathers`/`seasons` conditions), Noticeboard forecasts, and Three.js visuals.
- **Work items**:
  1. Create `src/game/environment.ts` composing Time of Day, Weather, Seasons, Player-Driven Changes, and NPC-Driven Changes (`EnvironmentSnapshot` + revision integer).
  2. Extract `src/scene/environmentRenderer.ts` with dirty-flagged visual updates, Gazebo brass clapper visibility fix (`models.ts`), Noticeboard dynamic flyer visibility, shared palette material cache (`models.ts`), instanced `light_rain`/`breeze` particles, `THREE.Timer`, and fixed frame-`dt` bell physics.
  3. Add edge-gated `onHudSync` in `NeighborhoodCanvas.tsx` / `App.tsx`, dirty-checked 5s autosave, lightweight pooled ambient NPC speech chips, and forecast/weather display in `App.tsx` / `JournalDrawer.tsx`.
  4. Write `environment.test.ts` and execute full browser QA (`1440×900` desktop + `390×844` mobile, software-GL check, v1 save upgrade check, 0 console errors).
- **Risk**: Medium-High (visual/FPS impact under software WebGL & mobile). Mitigated by instanced particle caps and `isSoftwareGl` verification in headless Chromium.

## 4. Estimated Complexity & Dependency Policy

- **Zero New NPM Dependencies**: Every Milestone 2 system (seeded PRNG, A* on <30 nodes, declarative dialogue topics, schema migrations, instanced weather FX) runs cleanly on existing TypeScript, React 19, and Three.js `0.187.0`.
- **Implementation Effort Estimate**:
  - **Phase A** (Foundation & Navigation): Small–Medium (~350–450 LOC + tests).
  - **Phase B** (NPC Sim & Relationships): Medium–Large (~550–700 LOC + tests).
  - **Phase C** (Declarative Dialogue Migration & Fixes): Medium–Large (~650–850 LOC, careful prose preservation + tests).
  - **Phase D** (5-Layer Environment, Weather FX & Scene Optimization): Medium (~450–600 LOC + browser QA).
- **Acceptance Gate Before Merge of Any Phase**:
  1. `npm test` (100% deterministic pass across all `src/game/*.test.ts` suites).
  2. `npm run lint` (`tsc --noEmit` — 0 errors).
  3. `npm run build` (`vite build` — clean bundle).
  4. Headless Chromium verification (`1440×900` & `390×844`) confirming 0 console errors, verified `v1 -> v2` save upgrade, and acceptable software-GL pacing.
